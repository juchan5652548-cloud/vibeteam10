# JOBFIT AI 4분 시연 및 질의응답

## 시연 준비

- 서비스: https://vibeteam10.vercel.app/ · 저장소: https://github.com/juchan5652548-cloud/vibeteam10
- 심사자는 본인의 GitHub 계정으로 로그인한다. 관리자 계정의 비밀번호를 공유하지 않는다. 별도 공용 심사용 계정은 아직 준비하지 않았다.
- 학습 분석을 보여 줄 계정에 실제로 푼 기록을 준비한다. 예시 기록을 실제 성과로 소개하지 않는다.
- 6문항 진단은 발표 전에 완료해 두고, 발표 중에는 문제 한 개를 풀어 저장과 분석 연결을 보여 준다. AI 요청은 한 번만 실행하고 대기 중에는 집계 기준을 설명한다.
- 무료 AI 한도에 걸리면 오류 안내와 기본 분석·추천이 유지되는 모습을 보여 준다. 저장해 둔 응답을 실시간 응답처럼 소개하지 않는다.

## 예상 질문과 근거

**AI가 실제로 동작하나요?**

로그인한 사용자가 버튼을 누르면 서버가 Gemini API에 요청한다. 문제별 힌트와 학습 통계 설명 두 가지가 있다. 모델명은 응답 아래 표시한다. 호출 방식은 `src/lib/ai-hint.ts`, 학습 통계 전송 항목은 `src/lib/learning-coach.ts`, 인증 및 오류 처리는 `src/app/api/practice/analysis/route.ts`에 있다.

**AI가 정답률을 계산하거나 문제를 채점하나요?**

아니다. 정답·해설은 서버 문제은행으로 채점하며 통계는 `src/lib/learning-analysis.ts`로 계산한다. AI는 계산된 통계를 설명한다. AI 설명이 항상 정확하다고 보장하지 않으며 실제 집계와 함께 확인하도록 안내한다.

**약점 판단은 얼마나 신뢰할 수 있나요?**

같은 지원 분야·영역에서 서로 다른 3문제 이상 풀었고 오답이 있는 경우에만 가장 낮은 정답률 영역을 복습 후보로 삼는다. 3문제는 제품의 최소 표시 기준이며 통계적으로 검증된 진단 기준이 아니다. 모두 맞힌 영역을 약점으로 분류하지 않는다. 시간만으로 능력 부족이나 채용 적합성을 판단하지 않는다.

**900문제는 모두 별개의 실전 기출인가요?**

자체 제작 연습문제다. 기존 150문항에 분야별 25개 유형군의 10개 변형씩 총 750문항을 추가했다. 고유 ID는 900개지만 추가 문제가 750개의 완전히 다른 유형인 것은 아니다. 구조 검사 및 추가 수리·순서 문제 500개의 독립 정답 검산을 완료했으며, 전 문항의 외부 전문가 검수나 실제 시험 적합성 인증은 하지 않았다. 상세 내용은 [문제은행 문서](JOBFIT_QUESTION_BANK.md)를 참고한다.

**누가 다른 사용자의 기록을 볼 수 있나요?**

일반 사용자는 서버 인증과 DB RLS로 본인 기록만 접근한다. 관리자 통계는 승인된 GitHub 계정의 변경 불가능한 provider ID로 제한하며, 화면 숨김만으로 보호하지 않는다. 구현과 검증은 [관리자 문서](JOBFIT_ADMIN.md)에 정리했다.

**개인정보와 비용은 어떻게 관리하나요?**

모델에 보내는 학습 데이터는 지원 분야·문항 수·정답률·평균 시간·오답 유형의 집계다. 무료 서비스의 데이터 이용 안내를 요청 전에 표시한다. 서버 비밀 키는 브라우저에 보내지 않는다. 무료 프로젝트를 사용하고 자동 유료 전환은 없다. 앱 요청 제한은 인스턴스 메모리 기준이므로 전역 한도라고 주장하지 않는다.

**동시 접속자가 늘어나면요?**

현재 배포와 소규모 동작은 검증했지만 대규모 부하 시험은 하지 않았다. 사용자별 최근 500회 기록을 읽으며 새 기능에 DB 테이블은 추가하지 않았다. 분산 요청 제한, 장기 집계, 부하 측정은 확장 단계다.

**AI나 저장 요청이 실패하면요?**

AI 오류·대기·재시도 상태를 표시하며 기본 채점과 통계·추천은 유지한다. 채점은 제출 ID를 재사용해 중복 저장을 막고, 재시도 시 최초 저장된 풀이 시간을 반환한다. 실패할 때 사용자가 고른 답안을 유지한다.

## 제출 전 남은 확인

- 실제 발표 연습과 질의응답 리허설은 별도로 진행한다.
- 주최 측에서 별도 심사용 계정을 요구하는지 확인한다. 이메일 가입은 SMTP 설정이 남아 있어 GitHub 로그인을 사용한다.
- 제출 마감 시점의 배포 URL·커밋·운영 상태를 다시 확인한다.
