## 이번에 고친 사항

1. 전체 분야 맛보기뿐 아니라 선택한 분야의 6문항 진단을 제공한다. 영역을 고르게 골라 진단하고 아직 풀지 않은 문제를 우선한다.
2. 결과 화면에서 ‘내 학습 분석 · 추천 복습’으로 바로 이동하며 진단한 지원 분야를 유지한다.
3. 서로 다른 지원 분야의 같은 이름 영역이 섞이지 않도록 집계 키를 분리했다. 같은 문제의 반복 제출은 독립 표본으로 늘리지 않고 마지막 답안만 반영한다.
4. 영역별 서로 다른 3문제 이상·오답이 있는 경우만 복습 후보로 삼는다. 모두 정답인 영역과 표본이 적은 영역을 억지로 약점으로 표시하지 않는다. 3문제는 제품 기준이며 검증된 심리측정 기준은 아니다.
5. 서버에 저장된 본인 통계로 AI 학습 조언을 받는다. 이름·이메일·계정 ID·답안 원문·날짜는 보내지 않으며 요청 전에 전송 안내를 보여 준다.
6. 채점 응답 후 타이머를 멈추고, 재시도 시 서버에 처음 저장된 시간과 화면 시간이 일치하도록 수정했다.
7. 전체 누적 현황과 분야별 분석 범위를 화면에 구분하고, 키보드로 화면을 전환할 때 본문으로 초점을 이동한다.

## 자동 검사와 실제 사용을 구분한 기록

- `node scripts/check-learning-analysis.mjs`: 실제 모듈로 집계·반복 제출·분야 분리·추천·전송 필드와 API 16개 조건·재시도 시간을 검증했다. 외부 인증·DB·공급자 I/O는 fixture다.
- `node scripts/check-ai-hints.mjs`: 힌트 요청 계약·안전한 실패·입력 경계·요청 제한 통과. 실제 AI 응답 여부는 이 검사만으로 판단하지 않았다.
- `node scripts/check-admin-access.mjs`: 관리자 API 19개 조건 통과.
- `node scripts/check-auth-rate-limits.mjs`: 인증 API 15개 조건 통과. 실제 계정이나 이메일은 생성하지 않았다.
- `python -X utf8 scripts/check-question-bank.py`: 전체 900문항, 분야별 300문항 구조 검사 통과.
- `python -X utf8 scripts/check-expanded-answers.py`: 추가 수리·순서 문제 500개의 정답을 독립 계산하여 통과. 이것이 전체 문항의 전문가 검수를 의미하지 않는다.
- TypeScript·ESLint·프로덕션 빌드 통과. 변경 파일은 Prettier 검사 통과. Windows 체크아웃의 기존 CRLF는 `--end-of-line auto`로 검사했다. 작업 도중 사용자가 수정한 README는 별도로 보존했다.
- 로컬 브라우저에서 실제 6문항을 제출하고 결과·분야별 분석·추천 5문항 시작을 확인했다. 대기업 기록만 있는 상태에서 공기업을 선택하면 풀이 전 안내가 나왔다. 이 검증은 운영 사용자 기록을 생성하지 않았다.
- 390×844 모바일에서 분석·추천·AI 안내를 확인했다. 문서 너비 375px, 뷰포트 390px로 페이지 가로 넘침이 없었다. 상단 메뉴는 자체 가로 스크롤이다.

## 배포 확인 및 반응속도

기능 커밋 `49389be`, Vercel 배포 `73reqYDe8GLuncuAkHEnN1NbURn7`의 완료를 확인했다. 운영 사이트에서 로그인한 소유자 계정으로 관리자 통계와 개인 기록을 확인했다. 새 학습 분석 화면에서 기존 기록을 바탕으로 `gemini-3.5-flash-lite`의 실제 한국어 답변을 받았고, 표본 부족을 안내하며 약점을 확정하지 않는 내용을 확인했다. 테스트를 위해 운영 계정의 풀이 기록을 추가하지 않았다.

첫 실제 답변에 영문 변수명이 섞이는 문제를 발견해 모델 입력의 필드와 분야 이름을 한국어로 바꾸고 설명 지침을 보완했다. 입력에 개인 식별 정보가 섞이지 않는 검사도 다시 통과했다. 프롬프트 변경만으로 모든 답변의 품질을 보장하지 않는다.

배포 후 `check-auth-boundaries.py`로 보호 페이지·API의 비로그인 차단, 잘못된 입력과 다른 Origin 차단을 확인했다. 새 분석 API도 비로그인 401, 다른 Origin 403, 잘못된 분야·사용자 ID 주입 400, 큰 본문 413을 확인했다. 관리자 API는 비로그인 401이었다. 게스트 채점 응답의 시간 반환도 확인했으며 로그인 쿠키를 사용하지 않아 DB 기록을 생성하지 않았다.

## 남은 개선점

- 분야별 300문항을 확보했지만 추가 750문항은 유형군별 변형을 포함한다. 전문가 검수와 더 다양한 유형을 늘려야 한다.
- 소규모 표본만으로 실력·채용 적합성·합격 가능성을 판정할 수 없다. 실제 사용자 연구와 학습 효과 측정이 필요하다.
- AI 요청 제한은 서버 인스턴스 메모리 기준이다. 분산 제한과 부하 시험을 아직 구현·실시하지 않았다.
- 이메일 가입의 SMTP 설정, 별도 심사용 계정 정책, 실제 발표 리허설은 남아 있다. GitHub 로그인을 사용한다.
- 이전 Supabase 점검의 비밀번호 유출 방지 비활성화와 `public.rls_auto_enable()` 실행 권한 권고는 이번 기능 변경으로 해결했다고 주장하지 않는다.
