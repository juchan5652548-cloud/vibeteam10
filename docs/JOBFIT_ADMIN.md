# JOBFIT AI 관리자 학습 현황

## 사용 방법

`juchan5652548-cloud` GitHub 계정으로 로그인한 뒤 왼쪽 메뉴의 **관리자 · 학습 현황** 또는 `/admin`을 연다. 이름·이메일 검색, 지원 분야 선택, 최근 학습순·풀이 수·오답 수·정답률 정렬을 제공한다. 회원 목록은 페이지당 50명이며, 요약 수치는 현재 검색 조건의 전체 회원 기준이다.

## 집계 기준

- **총 풀이**: 계정에 저장된 모든 제출 횟수. 같은 문제를 반복해서 풀면 각각 집계한다.
- **서로 다른 문제**: 중복을 제외한 문제 ID 개수.
- **정답·오답**: 저장된 선택지를 현재 서버 문제은행의 정답과 비교한 횟수.
- **정답률**: 정답 ÷ (정답 + 오답) × 100, 소수점 한 자리. 풀이가 없으면 `—`.
- **최근 학습**: 선택한 분야의 마지막 제출 시각, 한국 시간으로 표시.

삭제된 문제처럼 현재 문제은행에서 확인할 수 없는 제출은 총 풀이에 포함하지만 정답·오답·정답률에서 제외한다. 풀이 기록이 없는 회원도 목록에 나타난다. 게스트 브라우저 기록은 서버 집계에 포함하지 않는다. 기존 개인 오답노트의 최근 500회 조회 제한과 달리 관리자 통계는 저장된 전체 기록을 집계한다.

## 접근 권한

관리자는 Supabase `auth.identities`에 연결된 GitHub 제공자 ID `267583432`로 판별한다. 이 ID는 GitHub 공개 API에서 `juchan5652548-cloud` 계정과 일치함을 확인했다. 사용자가 수정할 수 있는 이름·이메일·`user_metadata`를 권한 근거로 쓰지 않는다.

서버 페이지와 `/api/admin/learning`은 Supabase `getUser()`로 로그인 세션을 검증한다. API의 권한 검사와 별개로 DB 집계 함수 내부에서도 관리자 여부를 검사한다. 비로그인은 401, 일반 회원은 403이며, 확인 실패 시 접근을 허용하지 않는다. 응답에는 `private, no-store`와 `Vary: Cookie`를 적용한다.

권한을 가진 DB 함수의 구현은 `jobfit_private` 비공개 스키마에 둔다. `public` 스키마의 RPC 진입점은 호출자 권한으로 실행되는 래퍼이며, 익명 실행 권한은 없다. 내부 구현도 매번 승인된 GitHub 신원을 검사한다.

앱은 기존 공개 Supabase 연결 키와 로그인 세션만 사용한다. 서비스 역할 키나 추가 환경 변수는 필요 없다. 서버 문제은행의 정답표는 서버에서 DB 집계 함수로만 전달하며 브라우저 응답에는 넣지 않는다. 기존 풀이·북마크 테이블의 본인 자료 접근 정책과 쓰기 권한을 확대하지 않는다.

## 적용 순서

1. Supabase 운영 프로젝트 `bpkamwzqwvsxundnxshr`에 관리자 통계 마이그레이션을 적용한다.
2. 기존 RLS·함수 실행 권한·지정 계정의 권한을 점검한다.
3. 앱 검사와 빌드를 통과한 커밋을 기존 Vercel 프로젝트에 배포한다.
4. 비로그인 차단, 일반 회원 차단, 지정 관리자 집계를 확인한다.

마이그레이션은 읽기 전용 집계 함수를 추가하며 기존 회원·풀이·북마크 데이터를 변경하지 않는다. 앱을 이전 버전으로 되돌려도 추가된 함수가 남을 뿐 기존 학습 기능과 호환된다.

## 검증

```sh
npm run check
npm run build
node scripts/check-admin-access.mjs
node scripts/check-admin-database.mjs
```

Windows의 `core.autocrlf` 체크아웃에서는 기존 파일의 CRLF 때문에 기본 포맷 검사가 실패할 수 있다. 타입·린트는 동일하게 실행하고 `node node_modules/prettier/bin/prettier.cjs --check . --end-of-line auto`로 내용과 체크아웃 줄바꿈을 검증한다. 이 경우 운영 Linux 빌드의 기본 검사 결과도 별도로 확인한다.

API 검사는 실제 Route Handler와 권한 함수를 불러와 19가지 성공·실패 경로, 위조 프로필, 조회 조건 제한, 비밀값 미노출과 캐시 헤더를 확인한다. DB 검사는 현재 잠금 파일에 포함된 PGlite를 이용해 별도의 메모리 PostgreSQL에 마이그레이션과 테스트 자료를 구성한다. 운영 계정을 만들거나 학습 자료를 쓰지 않는다. 반복 제출, 채점 불가 문제, 기록 없는 회원, 검색, 분야, 페이지 나누기와 기존 RLS를 검사한다.

운영 DB에서는 읽기 전용 트랜잭션에서 지정 계정의 JWT subject를 모의 설정하고 `authenticated` 역할로 조회한 뒤 롤백한다. 이 검사는 DB 권한과 집계 검증이며 실제 브라우저 GitHub 로그인 검증을 대신하지 않는다. 확인 시점의 회원 5명, 풀이 회원 3명, 제출 9회가 정답 2회·오답 7회로 일치했고 기존 북마크 1건도 유지되었다.

2026-10-30 로컬 타입·린트·줄바꿈을 고려한 포맷 검사, 운영용 빌드, API 19개 사례와 PostgreSQL 검사를 통과했다. 운영 DB에서는 지정 관리자 허용, 기존 일반 회원 차단, 익명 함수 실행 차단, 공개 스키마의 관리자 `SECURITY DEFINER` 함수 0개를 확인했다.

Supabase 보안 진단에서 새 관리자 함수 관련 권고는 해소되었다. 기존 `rls_auto_enable()`의 [실행 권한 권고](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable)와 이메일 인증의 [유출 비밀번호 검사 비활성화 권고](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)는 이번 관리자 기능과 별개인 기존 설정으로 남아 있다.
